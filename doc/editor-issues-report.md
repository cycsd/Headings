# 節點內編輯器：問題與解法報告

日期：2026-11-14。範圍：節點內編輯（嵌入式 Obsidian 編輯器）從第一版到目前為止遇到的問題、原因、解法與教訓。
設計共識的逐條紀錄在 `doc/mindmap.md`，這份只整理「出了什麼事、為什麼、怎麼修」。

## 架構回顧

- 核心（`src/core/edit.ts`）是純函式：樹 + 原文 → 文字補丁。不碰 DOM、不碰 Obsidian。
- `DocumentEditor`（`src/service/document-editor.ts`）是一份 headless CodeMirror 鏡像，帶 history。補丁先套到鏡像再用 `vault.process` 寫回；寫回時檔案內容必須等於鏡像套補丁前的內容，否則視為外部改動，丟衝突。
- `NodeEditing`（`src/view/node-editing.ts`）管進出編輯、掛 Obsidian 的嵌入式編輯器、新增 / 刪除 / 搬移 / 復原。
- 節點元件 `TreeNodeBox.svelte` 在編輯中把標題列與內容區換成 `.editor`，由 attachment 掛編輯器。

## 逐項說明

### 1. 進編輯立刻跳出

- 現象：雙擊進編輯，還沒打字就離開。
- 原因：「點外面離開」用編輯器的 blur 事件。嵌入式編輯器掛上後焦點切換、連結補全的彈窗、右鍵選單都會讓它失焦，但那不是使用者要離開。
- 解法：改用 document 層的 `pointerdown`（capture）判斷：目標在編輯器內、或在 `.suggestion-container / .menu / .modal-container / .cm-tooltip` 裡都不算離開；剛掛上的 300ms 內也不算。
- 教訓：焦點事件不等於使用者意圖；要判斷「使用者點了別處」就直接看指標事件。

### 2. Enter 不換行、畫面閃爍、新打的字消失

- 現象：按 Enter 沒有換行；有時打字後畫面閃一下，剛打的字不見，回到原文。
- 原因：掛編輯器的 attachment 在 effect 裡執行，裡面讀了 `node` 的欄位，被 Svelte 追蹤。編輯中節點長高 → 佈局重算 → `node` 相關訊號變 → attachment 重跑 → 編輯器被銷毀重建，內容回到原文。
- 解法：attachment 本體用 `untrack` 包住；另外加草稿 map，萬一真的被重掛（佈局切換等）也用草稿還原而不是原文。
- 教訓：Svelte 5 的 attachment / effect 會追蹤裡面所有訊號讀取；掛第三方元件的程式碼一律 `untrack`。

### 3. 清單接續不見了

- 現象：在清單項裡按 Enter，下一行不再自動帶 `- `。
- 原因：為了修問題 2 時一度自己接管 Enter，蓋掉 Obsidian 編輯器內建的清單接續。
- 解法：編輯器的預設按鍵一律不攔。Enter 綁在最低優先權，只有沒人處理時才補一個換行；Esc 維持 Obsidian 的「取消選取」。
- 使用者的決定：「編輯器有的預設按鍵都不要攔截」，連 Mod+S 也不要。

### 4. Mod+Enter（完成並寫回）無效

- 現象：按 Mod+Enter 沒反應，或觸發 Obsidian 的「切換核取方塊」。
- 原因：Obsidian 的全域快捷鍵走 `app.keymap`，在 document 層先於 DOM 監聽處理；在編輯器元素上加 capture 監聽攔不到。
- 解法：嵌入式編輯器有自己的 `Scope`，在它裡面 `scope.register(["Mod"], "Enter", …)` 並回傳 `false`，才搶得到。
- 教訓：Obsidian 裡要攔快捷鍵，用 Scope 不要用 DOM 事件。

### 5. 清單新增子節點不會進入編輯

- 現象：對清單項按 Tab 新增子項，文件有多一行，但畫面沒進入編輯；新增兄弟正常。
- 原因：新節點靠文字起點 `nodeStart` 找回。清單項的 range 從 `-` 開始、不含縮排，插入字串是 `\n` + 縮排 + `- `，起點要跳過縮排；子項比兄弟多一層縮排，算成 `at + 1` 就對不到。
- 解法：`nodeStart = at + 1 + indent.length`。
- 教訓：list item 的 range 不含縮排，所有算位置的地方都要記得。

### 6. deleteNode 的兩個範圍問題

- 巢狀清單項刪掉後縮排留在下一行前面：刪除範圍改從行首開始（前面只有空白時）。
- 刪清單最後一項後，原本隔開的空行被吃掉，下一段變成清單的延續：原本把後面的換行全部吃掉；改成接合處最多留一個空行（兩個換行），檔尾一個都不留。拖曳搬走清單最後一項走同一條路，一併修好。

### 7. 進編輯節點突然變很大

- 現象：雙擊一個只顯示標題的節點，節點瞬間撐到幾百像素寬、很高。
- 原因：兩個都是設計選擇。寬度設成「節點最大寬度」想讓打字有空間；標題節點的編輯範圍是「標題行到第一個子標題之前的全部內容」，所以整段原文都進來，高度只受「節點內容最大高度」限制。
- 第一版解法：新增「編輯器自訂尺寸」設定（寬度、最大高度），關閉時依現狀。
- 最終解法（與問題 9 一起改）：見下。

### 8. 進編輯後畫面卡死、佈局跑掉

- 現象：進編輯後整個 view 停住，截圖裡節點疊在一起、左對齊。
- 原因：為了「節點變大時保持在畫面內」，我用 ResizeObserver 在編輯器每次變大時呼叫 `revealNode`。它背後有兩個早就存在、但以前只在使用者點一下時才跑一次的放大器：
  - 收合集合不管有沒有變都 clear 再 add，三種佈局的 placement 都讀它，於是整棵樹重排。
  - 心智圖量尺寸的 attachment 每次 render 都是新函式，Svelte 會把全部節點 unobserve 再 observe，每個節點重新回報一次初始尺寸。
  CodeMirror 一次輸入會分幾個量測週期長高，每次長高都觸發以上全部，節點多的文件一個鍵就是幾百毫秒以上的停頓。截圖裡節點疊在一起是尺寸回報到一半的中間狀態。
- 解法：
  - `replaceCollapsed` 內容相同就不寫。
  - 編輯用 `requestReveal` 只設 reveal 請求，不碰收合、聚焦與選取。
  - 心智圖的量測 attachment 依節點 id 快取，placement 重算不再重新 observe。
  - 最後連 ResizeObserver 都拿掉了（見問題 9）。
- 教訓：找「放大器」而不只找「觸發器」。沒有觸發器時放大器看起來無害，接上高頻事件就炸。另外這次無法在 Obsidian 外重現，鏈是從程式碼推出來的；修法因此一併拆掉放大器，就算推錯環節也不會再炸。

### 9. 進編輯不自然地抖

- 現象：點開編輯器時畫面跳動幾下才停。
- 原因：編輯器跟著內容長。進入時寬高同時變 → 心智圖重排、「根節點不動」的補償平移 → ensure 再平移一次 → CodeMirror 即時預覽畫標籤、分隔線時高度再變幾次，每次都再來一輪。
- 使用者的反問：「好像沒必要一定需要讓節點一直變化高度？」是關鍵。
- 解法（設計改掉）：
  - 尺寸進入時一次定好、編輯期間不變，內容多了在編輯器內捲動。
  - 關閉自訂尺寸（預設）：依內容貼合。寬 = 原文最長一行的自然寬度，夾在節點原本的寬與節點最大寬度之間；高 = 以該寬度量原文換行後的高度，夾在節點原本的高與內容最大高度（0 時 50vh）之間。節點顯示的就是全部內容時幾乎不動。
  - 開啟自訂尺寸：寬 = 設定值；高量原文後至少 4 行、不超過編輯器最大高度。
  - 量測在掛 CodeMirror 之前用隱藏探針做（`src/view/editor-size.ts`），節點原本的大小用 `$effect.pre` 在 DOM 換成編輯器之前量。夾值邏輯是純函式，有測試。
  - 心智圖錨點：平常根節點不動；編輯中改成編輯節點靠根那一側的上角不動，兄弟往外讓；離開編輯後的第一次重排也沿用。
  - ensure 只在掛好後的下一個 frame 做一次。
  - 編輯器右下角 CSS `resize: both` 把手，使用者自己拉，離開編輯回復。
  - 游標放在開頭（標題行行首）；新增的節點放結尾、新段落全選佔位文字。
- 教訓：連續的小變動比一次大變動更煩人。能「一次定好」的就不要「跟著長」。

### 10. 編輯後節點自己展開 / 收合

- 現象：收合的子樹在編輯後展開，或別的節點被收合。
- 原因：節點 id 由內容組成：heading 是「父 id / 標題」，list item 與 section 是「父 id : 序號」。改標題、在前面插入或刪除兄弟，節點與整棵子樹的 id 都變。收合、icon 列、點亮型別、選取、聚焦都用 id 記，id 一變就對不上，拿到舊 id 的另一個節點反而繼承了狀態。
- 解法（`src/view/id-remap.ts`）：
  - 寫回前記下每個節點在原文的起點。
  - `DocumentEditor.apply / undo / redo` 回傳實際套上的補丁（ChangeSet 轉 TextPatch），復原重做也能搬。
  - cache 更新後把起點穿過補丁算到新位置（純插入時插入點上的節點讓開；取代時 from 上有插入文字的節點留在原位、空字串代表刪除），用起點在新樹找回同一個節點，把狀態搬到新 id。
  - 拖曳搬移的子樹起點對不回去，改用新位置節點的 id 換前綴。搬移的復原會掉那棵子樹的狀態（已知限制）。
  - 時序：cache 更新是非同步的，編輯中擱置的舊版可能比自己寫回的那版先送到。記下寫回前後的文件內容，舊版直接略過（連鏡像都不動，否則會清掉 history），自己那版才搬狀態與處理新節點，其他內容代表別人改了就放棄等待。
- 後續（已定案並實作）：使用者問「改用段落順序當 id 會不會更適合」。兩種 id 都會漂，只是時機不同；外掛內的變動靠搬狀態兩種都沒問題，差別只剩使用者在 Markdown 編輯器直接改文件時，標題式只在改標題時漂、順序式在任何插入刪除時都漂，所以維持標題式。外部變動也搬狀態：用鏡像與新文件的差異化成一個補丁走同一條路，差異以「行」為單位找共同前綴 / 後綴（字元級會把「在 B 前面插入 New」算成「B 改名 New 再插入 B」，節點起點就對到錯的節點）。

### 11. 打開時出捲軸、太小的節點編輯器太窄

- 現象：只有「# H1」的節點打開編輯器，框跟節點一樣小，內容被裁、兩個方向都有捲軸。
- 原因：探針用內文字級量「# H1」，即時預覽把標題畫成 H1 的大字，實際又高又寬；標籤膠囊、程式碼區塊也有同類誤差。
- 使用者的要求：打開時高度剛好裝下全部內容、不出捲軸，之後多打超過才出；太小的節點要有可用的寬度。
- 解法：
  - 高度畫完再定：掛上時用估算值，CodeMirror 畫完即時預覽後（兩個 frame 後，250ms 再補量一次）量實際內容高度，夾在「不低於節點原本的高、不高於上限」後修正一次並鎖住；可放大也可縮小；使用者自己拉過就不再碰。
  - 寬度：關閉自訂時下限改成「節點原本的寬與 200px 取大者」；探針逐行套用 Obsidian 的 `--h1-size` 到 `--h6-size` 與等寬字，寬標題不再被低估。
- 教訓：估算值只能當第一幀，真正的尺寸要向渲染結果要；但只要「修正一次就鎖住」，就不會回到問題 9 的抖動。

## 尚未在 Obsidian 內驗證的點

- Mod+Enter 經由 Scope 的行為、Mod+Z 焦點歸屬、衝突 Notice、刪除確認框。
- 手機：軟鍵盤、觸控選取文字、離開編輯的手勢。
- 依內容貼合的尺寸在即時預覽（標題字級、標籤膠囊）下的誤差是否可接受。
- 編輯器比視口大時 ensure 對齊左上的手感。

## 整體教訓

1. **先問「需不需要變」再問「怎麼平滑地變」。** 抖動、當機兩題的最終解都是讓尺寸不變，而不是把變化做得更順。
2. **第三方元件掛在反應式框架裡一律 `untrack`。** 問題 2、8 都是追蹤到不該追蹤的訊號。
3. **狀態用內容導出的 id 記，就要有搬 id 的機制。** 或者反過來，任何改文件的路徑都要回報「改了哪裡」。
4. **Obsidian 的快捷鍵與焦點有自己的規則。** 攔鍵用 Scope、判斷離開用指標事件，不要靠 DOM 的 keydown 與 blur。
5. **無法重現時，修法要同時拆掉放大器。** 推論可能錯，但代價降低了就不會再炸。
